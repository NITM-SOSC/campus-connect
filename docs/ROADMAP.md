# Roadmap (Proposed)

This roadmap describes possible stages for an early-stage initiative. It is not a delivery schedule, funding commitment, institutional approval, or promise that any feature will ship. The project currently provides repository documentation only; there is no working application.

## 1. Establish the project foundation — in progress

- Publish project purpose, contribution guidance, and community standards.
- Identify open questions and invite discussion from prospective contributors.
- Agree on how project decisions and scope will be recorded.

## 2. Explore needs and requirements — proposed

- Gather and compare use cases for students and other intended participants.
- Consider accessibility, privacy, moderation, safety, and data-minimization needs.
- Clarify what is in scope and what should not be collected or supported.
- Prioritize a small, testable initial problem before designing a broad platform.

## 3. Make foundational decisions — proposed

- Evaluate technology and architecture options against documented requirements and contributor capacity.
- Decide whether any identity, data, moderation, or operational dependencies are acceptable.
- Document decisions and establish suitable quality, security, and testing practices.

## 4. Build and validate an initial slice — proposed, not started

- Implement only a community-reviewed, clearly scoped initial capability.
- Test it with appropriate users and revise based on evidence.
- Document setup, limitations, and maintenance responsibilities.

## 5. Grow deliberately — future possibility

- Consider additional functional areas only after the initial slice and its support needs are understood.
- Review privacy, security, accessibility, and maintenance implications with each expansion.

## Current status

Only the repository foundation is being established. The functional areas in the [architecture proposal](ARCHITECTURE.md) are ideas for discussion and are not implemented. There are no target dates or deployment plans.
